# Plush and Pip Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship two new styles, `plush` (fuzzy felt critter + accessory) and `pip` (geometric form + pill eyes), wired through every wrapper and the site, with one hue per seed across all styles.

**Architecture:** Each style is a `Style<O>` in `packages/core/src/styles/`, exported as its own subpath. Both call `pickBase(rng, palette)` first, take all their own draws from one `rng.fork(<name>)` in a fixed order, and paint colors through `colorVars()` so `--avatar-c1` is the body.

**Tech Stack:** TypeScript, tsdown, vitest (node + browser), size-limit, Astro site.

**Spec:** `docs/superpowers/specs/2026-11-11-plush-pip-design.md`

## Global Constraints

- No SVG filters, no runtime deps, no `Math.random`.
- Same seed + palette → same `hue` pick as every other style.
- Options set to their default give exactly the unset SVG; option order never matters.
- Unknown option strings fall back to defaults, never throw.
- Existing frozen checksums in `frozen-1.json` must not change; new styles are only added.
- Budgets (gzip): core + plush ≤ 8 KB, core + pip ≤ 5 KB.

## Review Focus

- `__proto__` / `toString` as `accessory` or `form` → default, no throw (covered in each style test).
- Forcing the drawn accessory/form → identical picks (pick-order test).
- Tufts and accessories inside the 0..100 frame for 300 seeds (geometry test).
- Eyes on a thin form tip (triangle, drop) → eyes sit on the inscribed center (geometry test).
- 24px legibility: pip eyes not thinner than ~3 units (asserted in pip test).
