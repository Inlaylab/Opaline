# Opaline Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the shadcn-feel Astro site (hero, playground, gallery, docs) and deploy it to GitHub Pages.

**Architecture:**

- `apps/docs` stays one Astro project.
- Layout, components and styles live in `src/`.
- `src/scripts/playground.ts` imports the core and the styles and renders on input.
- The gallery uses `<opaline-avatar>`.

**Tech Stack:** Astro 7, plain CSS variables, the Opaline core, the element, and Playwright for the smoke test.

**Spec:** `docs/superpowers/specs/2026-11-04-site-design.md`

## Global Constraints

- Branch `feat/site`. Conventional Commits, no AI attribution lines.
- No new runtime dependencies besides the workspace packages. Playwright and vitest come from the workspace.
- `base: '/Opaline'`, so every link and asset goes through `import.meta.env.BASE_URL`.
- Works at 375 px with no horizontal scroll, in both themes.

## Review Focus

1. **The playground shows the core's output.** Test: the smoke test compares the preview SVG with `createAvatar` for the same options.
2. **Input from a user.** An empty seed, emoji, `<script>` or a very long string renders without breaking the page; the core escapes it. Test: the smoke test types `<b>x</b>` and checks that no `<b>` element appears in the preview.
3. **Theme toggle.** It persists, and falls back to the system setting when storage throws. Test: the smoke test toggles, reloads and checks.
4. **Phone width.** Test: at 375 px, `scrollWidth <= clientWidth`.
5. **Pages base path.** The built HTML references `/Opaline/` assets only. Test: grep the built HTML for `src="/_astro` with no base (it must not appear).
